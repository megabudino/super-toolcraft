## Decisions

### Renderer

- Decision: Use one canonical WebGL2 pipeline that keeps untouched rectangular cells as Coons patches and triangulates only cells containing independently added points, with up to 16 draggable colors and an export-excluded SVG editor portal.
- Reason: Existing Bezier boundaries and preset output stay intact while each added point becomes part of the rendered surface without changing the structural column count or canvas dimensions.
- Evidence: `src/app/mesh-gradient/mesh-webgl.ts`, `src/app/mesh-gradient/mesh-cell-triangulation.ts`, `src/app/mesh-gradient/renderer-pipeline.ts`, `src/app/mesh-gradient/mesh-editor-overlay.tsx`, and the exact independent-point browser scenario.

### Timeline

- Decision: Enable the Toolcraft playback timeline with a six-second seamless forward-only harmonic loop and editable duration.
- Reason: Users can play, pause, scrub, change duration, and export the animation; the first and last phases must stitch without mirror or ping-pong behavior.
- Evidence: `src/app/app-schema.ts`, `src/app/mesh-gradient/mesh-webgl.ts`, and the timeline browser evidence in `e2e/app-controls.spec.ts`.

### Layers

- Decision: Do not enable the Layers panel.
- Reason: The product edits one composited mesh-gradient output; point handles are editor overlays, not independently ordered product layers.
- Evidence: `appSchema.panels.layers` is omitted and export-clean browser evidence proves handles are excluded.

### Controls

- Decision: Use the built-in image picker for twelve mesh-only starting scenes and a product-owned `meshColorPoints` control for shared panel/canvas selection plus one-item Add/Remove; keep structural Bezier shaping and direct point dragging on the canvas.
- Reason: `collectionActions` can own a color array but cannot display the active canvas point, protect structural Coons nodes, or attach exactly one added color to one host cell. The custom renderer uses only Toolcraft Button/Input primitives and runtime commands.
- Evidence: `src/app/app-schema.ts`, exported `appControlSectionInventory`, `src/app/mesh-gradient/mesh-color-points-control.tsx`, `src/app/mesh-gradient/mesh-collection-topology.ts`, `src/app/mesh-gradient/mesh-canvas.tsx`, and `src/app/app-acceptance-data.ts`.

### Export

- Decision: Provide sticky Export PNG and Export SVG actions side by side above a full-width Export Video action. PNG/JPG and raster-backed SVG use selected 2K/4K/8K still sizing; video uses Current/4K encoder-safe sizing with MP4 capability fallback to WebM.
- Reason: The product is animated but users also need still frames, an exact portable SVG container, transparent output, and a safe browser-native video container. Raster embedding preserves the WebGL mesh exactly instead of claiming unsupported editable vector patches.
- Evidence: `src/app/mesh-gradient/mesh-export.ts` and decoded PNG/SVG/video artifact checks in `e2e/app-exports.spec.ts`.

### Performance

- Decision: Keep the existing point-count workload envelope, retained WebGL resource, 64/16 preview tessellation, and 32-step export path; mark local cell triangulation as an owner of preview, handle, and export passes.
- Reason: Independent insertions increase triangles only within the already enforced 16-point maximum and do not add a new pass, animation loop, backing-resolution change, or external input dimension.
- Evidence: `src/app/app-performance.ts`, `src/app/app-performance-impact.json`, `src/app/mesh-gradient/mesh-cell-triangulation.ts`, `src/app/mesh-gradient/mesh-canvas.tsx`, `src/app/mesh-gradient/mesh-webgl.ts`, and focused 12→13 plus rapid 12→16 browser inspection.
