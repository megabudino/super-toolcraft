## 1. Симптом A — резкая полоса в верхней зоне при вертикальном драге

**Где:** `hero-dispersion-post-shader.ts`, цикл дисперсии и цикл aura:

```glsl
vec2 offset = direction * span * spread + motionVelocity * spread * 2.0 + perpendicular * (...);
// aura: direction * (span * 2.6 + 24.0) * haloSwing * spread + motionVelocity * spread * 3.0 + ...
```

**Механизм.** Статичное смещение зоны (`direction·span`, для верхней полосы `direction = +dirPhi`,
т.е. вверх; `span` у кромки при настройках пользователя ≈ 100–200 px) и смаз движения
(`motionVelocity·2`, при драге упирается в клип 140 px ⇒ ±280 px) умножаются на **один и тот же**
`spread ∈ [−0.5, 0.5]`. Итоговый радиус смаза — `|direction·span + 2·motionVelocity|·0.5`. При драге
вниз контент движется вниз, `motionVelocity` антипараллелен `direction` ⇒ слагаемые вычитаются:
`|span − 2·|v||` вместо `span + 2·|v|`; при близких величинах — почти ноль ⇒ резкая область ровно там,
где `edge → 1` (у кромки), с рваным краем от турбулентности (она модулирует `span`). Боковые зоны не
страдают: их `direction` горизонтален и ортогонален вертикальному движению; автономное движение рядов
горизонтально и с верхней зоной не конфликтует; нижняя зона при драге вниз, наоборот, получает
усиленный смаз, а при драге вверх резкая полоса переезжает вниз. В per-card шейдере референса
формула была та же, но скорость не превышала единиц px, и эффект был незаметен.

**Правка (минимальная, сохраняет одномерный «спектральный хвост» референса).** Согласовать знак
слагаемого движения с направлением зоны в обоих циклах:

```glsl
float motionSign = dot(direction, motionVelocity) < 0.0 ? -1.0 : 1.0;
vec2 motionSmear = motionVelocity * motionSign;          // один раз перед циклами
offset = direction * span * spread + motionSmear * spread * 2.0 + perpendicular * (...);
// aura: ... + motionSmear * spread * 3.0
```

Так как `spread` симметричен, переворот знака не меняет центр ядра, а `|a + b|² = |a|² + |b|² + 2a·b ≥
|a|² + |b|²` при `a·b ≥ 0` ⇒ радиус никогда не меньше каждого из слагаемых. Альтернатива (если
одномерный хвост визуально не понравится): независимый `spreadM` для движения из перестановки
индекса (`fract((index + 0.5)·0.6180339887 + jitterM) − 0.5`) — два смаза сворачиваются в 2D-ядро,
дороже по шуму, не делать без запроса.

## 2. Симптом B — дёрганье при остановке

**Где:** `hero-sphere-gallery-webgl.ts` (`setSettings`, `draw`), `hero-sphere-gallery-motion.ts`
(`estimateHeroPanAngularRate`, `stepHeroAngularMotionState`), post-шейдер (`drift`, `haloSwing`,
`haloWave`, `motionKick`, `sampleScene`).

Три причины, складывающиеся в один симптом:

| # | Причина | Эффект |
| --- | --- | --- |
| B1 | Оценка скорости пана берётся **по приходу settings**, а не по кадрам: `rate = Δ / clamp(dt, 1 мс, 50 мс)`, где `dt` — интервал между сообщениями моста. Сообщения приходят пачками (rAF-коалесценция в Toolcraft + `postMessage`): два в одном кадре ⇒ `dt ≈ 1–2 мс` ⇒ rate завышен в 8–16 раз, причём `pendingPanRate` хранит только последнее; кадр без сообщений ⇒ цель сглаживания = 0 (пила). Итог: во время любого драга смаз почти всегда сидит на клипе 140 px, а после остановки завышенный rate сначала долго держит клип (`0.8ⁿ` от сотен рад/с), потом за ~12 кадров падает до нуля — «зависло и сорвалось». | Запаздывающее и резкое исчезновение смаза. |
| B2 | Турбулентность и aura привязаны к **мгновенной** скорости: `drift = dot(v, direction)·freq·0.3` сдвигает координату `fbm` (при `v = 140`, `freq = 1/130` — на 0.32 ячейки шума ⇒ совершенно другой контур), от той же `envelope` зависят `span`, `haloSwing` и перпендикулярный сдвиг halo `haloWave·34` (до ±12 px). В референсе `v` были единицы px и `drift ≈ 0.01`. При остановке за время затухания весь контур зоны и halo «переползают» в положение покоя. | Контур дисперсии и halo дёргаются при каждом старте/остановке. |
| B3 | `sampleScene` **клампит** UV к границе scene-буфера, а вертикальное поле буфера всего 80 px. Вертикальный смаз ±280 px плюс aura (до ~450 px) у верхней/нижней кромки читают одну и ту же крайнюю строку текстуры ⇒ полосы-«растяжки» цвета кромки на время драга, исчезающие при остановке. В per-card шейдере выборки вне bleed возвращали **прозрачность**. | Дёрганье у верхней/нижней кромок. |

Дополнительно: `motionKick` (+70 % яркости gate при `v = 140`) и `motionVelocity·2` в ядре затухают
плавно — это не дефект, но они усиливают ощущение «срыва», пока B1 держит клип.

**Правки.**

- B1 — измерять скорость **по кадрам**: в `draw` считать `Δ = Θ0/Φ0(now) − Θ0/Φ0(prev frame)` (с
  учётом `turns` и wrap), копить окно последних 4 кадров (`ΣΔ / Σdt`, `dt` кадра с клипом `[8, 50] мс`)
  и сглаживать `0.3` к этой оценке каждый кадр (ноль — когда за кадр ничего не пришло). Удалить
  `pendingPanRate`, `lastPanTimestamp`, `estimateHeroPanAngularRate` (заменить юнит-тесты на тест
  окна: пачка из двух сообщений в одном кадре даёт ту же оценку, что одно сообщение с суммарным Δ;
  остановка даёт монотонное затухание ниже `motionEpsilon` за ≤ 20 кадров; медленный драг даёт
  скорость, пропорциональную реальной). Расписание кадров — без изменений.
- B2 — отвязать шум от мгновенной скорости: `drift = clamp(dot(v, direction)·freq·0.3, −0.05, 0.05)`
  (диапазон референса), `haloWave`/`haloSwing` наследуют стабильность через `envelope`; `motionKick`
  оставить. Проверить, что при `v → 0` контур не меняется более чем на ширину одного пикселя.
- B3 — `sampleScene`: вне `[0, 1]` по UV возвращать `vec4(0.0)` (паритет с `sampleCard`), сгладить край
  на один тексель (`smoothstep`, как в `HERO_SCENE_FRAGMENT_SHADER`); вертикальное поле
  `verticalMargin` 80 → 256 (симметрично горизонтальному; память +~15 %). Оценить по ручной проверке,
  нужно ли больше — если aura у кромки всё ещё обрезается заметно, ограничить её reach клипом
  `min(span·2.6 + 24, 320)`.

## 3. Целевое поведение

- **M1** — в верхней/нижней зонах смаз при вертикальном драге не слабее, чем вне зон; при драге вверх
  и вниз картина симметрична.
- **M2** — интенсивность смаза пропорциональна реальной скорости (медленный драг — слабый смаз, клип
  140 px только при быстром); после остановки смаз затухает монотонно за ~0.3 с без фазы «зависания».
- **M3** — контур зоны и halo при старте/остановке движения остаются на месте (сдвиг ≤ 1 px).
- **M4** — у верхней/нижней кромок нет растяжек цвета во время драга; за кромкой — прозрачность.
- **M5** — Rows и статичная картина (без движения) не меняются побайтно (snapshot до/после при
  `speed = 0` и без пана совпадает).
