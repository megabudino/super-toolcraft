## 1. Модель: «загрузка активирует свой ряд»

Владение кардинальностью остаётся у пользователя (`Rows`, `+`/`−`); загрузка становится
**комплементарным писателем**, объявленным в interaction ownership:

1. **Активация.** Переход дропа Row N из пустого в непустой (появление первого ассета в
   `sphere.rowImages.(N−1)`), когда `N > rows.length`, **дорастает** коллекцию `sphere.rows`
   дефолтными рядами (`HERO_SPHERE_ROW_DEFAULT`) до длины `N` — одним диспатчем
   `controls.setValue` (label «Activate Row N», обычная history — undo откатывает активацию).
   Появившиеся промежуточные ряды без контента остаются пустыми полосами — это уже принятое
   Delivery 38 поведение («empty sibling row keeps its grid position»), 1:1 маппинг Row N ↔ ряд N.
2. **Триггер — переход, не состояние.** Эффект хранит предыдущее множество занятых индексов
   дропов (ref) и реагирует только на **новые** занятые индексы. Следствия, все намеренные:
   `Remove Row` при непустом дропе удаляет ряд, и эффект молчит (дроп-набор не менялся) —
   поведение Delivery 38 «drop retains the asset after Remove Row» сохранено; на маунте/после
   перезагрузки эффект только запоминает текущее состояние и **ничего не диспатчит** — удалённый
   ряд не реанимируется персистом; auto-shrink нет — удаление последней картинки ряд не убирает.
3. **Уже висящие загрузки** (текущая ситуация: 6 дропов заполнены, рядов 4) активируются либо
   `Add Row` (работает уже сейчас), либо любой новой загрузкой в этот дроп (переход «непустой»
   зафиксируется как новый занятый индекс после маунта только если до этого дроп был пуст —
   поэтому для существующих залежей канонический путь `Add Row`; описания контролов это говорят).
4. **Потолки не меняются:** рядов ≤ 6 (активация приходит только с дропов 1..6), картинок ≤ 8 на
   ряд, `minItems: 1` у `Rows` цел.

## 6. Риски

- **Порядок гидрации персиста:** медиа и values восстанавливаются асинхронно — эффект на
  маунте только запоминает состояние, поэтому любой порядок безопасен; jsdom-тест фиксирует
  «нет диспатча на первом вызове».
- **Undo-петля:** undo активации возвращает rows назад при непустом дропе — эффект молчит
  (перехода нет), повторная активация только новой загрузкой/`Add Row`; это осознанно (undo
  уважается) и записано в worklog.
- **Ожидание пользователя по залежам:** уже загруженные Row 5/6 не активируются сами при
  апдейте — один раз `Add Row` ×2 либо новая загрузка; сказать пользователю при сдаче.
- **Одновременная активация двух дропов** (маловероятно в UI) ⇒ один диспатч до max — покрыто
  unit-тестом.
