# Studio Room — настраиваемый эффект комнаты: две сетки, глубинный шлейф движения, живой шафл плиток (план реализации)

> **For agentic workers:** план рассчитан на выполнение по задачам (checkbox `- [ ]`) с
> `superpowers:subagent-driven-development` или `superpowers:executing-plans`. Preflight из
> `AGENTS.md` → `docs/toolcraft/workflow.md` (приложение **studio-room**) обязателен. Этот файл —
> единственный документ доставки.
>
> **Контекст.** Эффект живёт на сайте в `pre-footer-room.tsx`: одноточечная комната (SVG‑сетка к
> задней стене), плитки-картинки на поверхностях через matrix3d‑гомографию, параллакс за курсором
> на пружине, жёсткий свап всех плиток раз в 1–2 с. Toolcraft‑приложение `studio-room` — пока
> оболочка (iframe + высота канваса, контролов нет, протокол v1). Задача: сделать эффект
> настраиваемым из Toolcraft и интереснее. Согласованный состав: настройки геометрии/сетки/плиток/
> движения; **две настраиваемые сетки** (основная, в ячейках которой появляются картинки, и более
> мелкая блеклая — у обеих шаг, цвет, opacity, толщина); **глубинный шлейф движения** (увод
> вправо ⇒ левая сторона пускает дополнительные линии вглубь и затухает — и так для каждой
> стороны); плюс принятые предложения: по-плиточный шафл без мигания, стиль Slide (переезд по
> поверхности), глубинный туман, отклик плиток на курсор, «проявка» появления, скролл‑довесок,
> свои картинки через fileDrop, свитч анимации. **Режим доставки — основной функционал: глубокие
> контрактные проверки не делаем, только необходимые** (обязательные валидаторы приложения +
> focused‑юниты + один smoke‑кейс браузера; подробнее §5) — так решил пользователь. Протокол
> приложения v1 → v2. Запись в worklog — следующая итерация (`### Iteration 2 — …`, сверить).
> Коммиты — только по явной просьбе.

## 1. Модель настроек (таргеты Toolcraft ⇄ payload сайта, v2)

- **Room** — `room.depth` (0–1, дефолт ≈ текущий пресет «thirtyPercentDeeper»: интерполяция
  прямоугольника задней стены между мелкой и глубокой границами вокруг существующих пресетов);
  `room.vanishing` (vector‑pad, x/y ∈ −1..1, смещение задней стены до ±12% вьюбокса; сетка и
  плитки следуют автоматически — вся геометрия уже выводится из `BACK_WALL`).
- **Main Grid** (основная; в её ячейках живут плитки) — `grid.columns` (4–16, дефолт 8),
  `grid.rows` (2–8, дефолт 4), `grid.depthDivisions` (2–8, дефолт 4), `grid.color` (color,
  дефолт текущий цвет линий), `grid.opacity` (0–100%), `grid.thickness` (0.5–4 px,
  stroke-width). Ячейки плиток = деления этой сетки (как сейчас), крайние колонки/ряды
  по-прежнему исключаются из посадочных мест.
- **Fine Grid** (декоративная мелкая) — `fineGrid.enabled` (switch, дефолт вкл),
  `fineGrid.subdivision` (2–6, дефолт 3 — во сколько раз мельче основной, линии кратно между
  основными, чтобы сетки были согласованы), `fineGrid.color`, `fineGrid.opacity` (дефолт заметно
  ниже основной), `fineGrid.thickness` (0.5–2 px).
- **Tiles** — `tiles.perSurface` (1–4, дефолт 2; случайная «+1» на одной поверхности остаётся
  встроенной приправой), `tiles.interval` (0.4–5 с, дефолт 1.4 — период смены **одной** плитки,
  встроенный джиттер ±40%), `tiles.shuffleStyle` (segmented `Swap | Slide`),
  `tiles.develop` (0–1, «проявка» появления: blur→резкость+opacity, 0 = чистый фейд),
  `tiles.hoverLift` (0–1, приподнимание плитки возле курсора: scale до ~1.04 + мягкая тень;
  0 = выкл), `tiles.fog` (0–1, глубинный туман: затухание плиток и линий к задней стене).
- **Tile Images** — fileDrop (`tiles.images`, assetKind image, multiple, hardMax 12).
  **Основной источник контента — загрузки пользователя (его решение): в комнате показываются
  именно те картинки, которые он загрузил**, в порядке медиа, без подмешивания авторских.
  Авторские девять остаются только состоянием «ничего не загружено» (свежий дефолт и
  standalone‑сайт — см. §7 про медиа вне Toolcraft). Медиа‑канал в iframe — по образцу
  fine-details: дериват ≤1024 px, отправка один раз, кэш по ref. Если загружено меньше картинок,
  чем посадочных мест, картинки переиспользуются по кругу; если больше — шафл черпает из всего
  пула.
- **Motion** — `motion.enabled` (switch, глобальный вкл/выкл анимаций комнаты: параллакс, шафл,
  шлейф; выкл ⇒ статичная комната), `motion.parallax` (0–150%, дефолт 100% = текущие ±130/±100
  и ±13vw/±10svh, масштабирование диапазонов), `motion.smoothness` (0–1, дефолт 0.5 = текущая
  пружина 135/24; маппинг на stiffness/damping), `motion.scrollNudge` (0–1, дефолт 0.35 —
  небольшой довесок offsetY от прогресса скролла секции; 0 = выкл).
- **Depth Trail** («шлейф в глубину») — `trail.enabled` (switch, дефолт вкл), `trail.amount`
  (1–3, дефолт 2 — сколько дополнительных линий вглубь между соседними основными на активной
  стороне), `trail.strength` (0–100%, пиковая opacity шлейфа), `trail.fade` (0.2–2 с, дефолт
  0.7 — затухание до обычной геометрии).
  **Механика:** четыре огибающие по сторонам (left/right/top/bottom). Скорость пружинного
  смещения комнаты (`useVelocity` от spring‑значений) проецируется в стороны: движение вправо ⇒
  цель огибающей **левой** стороны = clamp(|v|/scale, 0..1) (и симметрично: влево ⇒ правая,
  вверх ⇒ нижняя, вниз ⇒ верхняя); атака мгновенная, спад экспоненциальный с `trail.fade`.
  Рендер: заранее построенные группы дополнительных «линий вглубь» (та же геометрия, что у
  существующих `AnimatedLine`, но на промежуточных позициях fine‑шага, только соответствующая
  сторона вьюпорта), opacity группы = огибающая × `trail.strength`. Никакого перестроения DOM в
  кадре — только 4 motion‑значения opacity.
- **Живой шафл (замена мигания).** Вместо пересборки всей раскладки: каждые `interval`(±40%)
  меняется **одна** случайная плитка — выбирается свободная ячейка (и картинка из пула, не
  занятая сейчас); `Swap` — старая гаснет, новая проявляется (`develop`); `Slide` — если новая
  ячейка на той же поверхности, углы гомографии анимируются от старой ячейки к новой (~0.6 с,
  ease), иначе фолбэк на Swap. AnimatePresence по стабильному id плитки. Вся случайность —
  через инъецируемый `random` (юнит‑тестируемость); `prefers-reduced-motion` ⇒ статичная
  раскладка, параллакс и шлейф выключены (как сейчас).

## 4. Целевое поведение

- **M1** — дефолты воспроизводят текущий вид комнаты; все секции панели меняют картинку живьём.
- **M2** — две сетки: основная (шаг/цвет/opacity/толщина, в её ячейках плитки) и согласованная
  мелкая блеклая (кратный шаг, свои цвет/opacity/толщина, выключаемая).
- **M3** — шлейф: увод курсора вправо ⇒ левая сторона пускает дополнительные линии вглубь и
  плавно затухает к обычной геометрии (`fade`), симметрично для всех четырёх направлений;
  amount/strength/fade настраиваются; выключаемо.
- **M4** — плитки живут по одной: без мигания всей комнаты; Slide скользит по поверхности с
  честной перспективой; проявка и hover‑отклик настраиваются; в комнате — только загруженные
  пользователем картинки (fileDrop, порядок медиа, недостающие переиспользуются по кругу);
  авторские — исключительно при полностью пустом дропе.
- **M5** — туман усиливает глубину; параллакс/пружина/скролл‑довесок настраиваются;
  `motion.enabled` выкл ⇒ статичная комната; reduced motion уважается.
- **M6** — Apply переносит настройки на standalone‑сайт; протокол v2 синхронен.

## 7. Риски и границы

- Slide между разными поверхностями не делаем (фолбэк Swap) — переезд через угол комнаты требует
  склейки двух гомографий; отдельная доставка, если захочется.
- Шлейф — про линии сетки, не про плитки: плитки при движении не размазываются (это другой
  эффект; можно обсудить отдельно).
- Лёгкий режим проверок означает: часть регрессий ловится только ручной приёмкой пользователя;
  обязательные валидаторы приложения всё равно должны быть зелёными — «пропустить» их нельзя,
  иначе схема не собирается.
- Медиа‑канал добавляет картинкам плиток дериваты ≤1024 — при желании крупнее это константа.
- Как и в других приложениях, Toolcraft‑медиа не переносится на standalone‑сайт: загрузки
  пользователя видны в превью Toolcraft, а сайт после Apply показывает авторский набор (рефы вне
  iframe не резолвятся). Перенос реальных файлов пользователя на сайт — отдельная задача
  (коммит картинок в `public/` — можно следующей доставкой, если нужно).
- Пружина/огибающие завязаны на rAF Motion; на скрытой вкладке всё замирает штатно.
- Apply — dev‑only запись файла (как у fine-details); продакшен‑деплой настроек остаётся ручным
  коммитом applied‑файла.
